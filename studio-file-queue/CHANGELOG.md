# CHANGELOG

## 4.0.1

- 删除构建输出的旧编码选择：译文和官方包内未翻译的 TSV/CSV/INI/TXT/LUA 一律写成 UTF-8。
- 全包转码同时在资源物化与最终构建边界执行；自动恢复表头、标签、路径或代码块后再次转码，防止旧字节被悄悄带回。
- 新增严格 UTF-8 发布闸门及新增 `U+FFFD` 拦截；非 UTF-8 文本不会进入 PAK。
- 标签、资源路径和 Lua 代码/坐标校验改为先按完整上下文解码再比较语义，允许纯编码字节变化，但继续阻止真实结构变化。
- 当前 `pak/xxx` 三包真实重建及全条目回读通过：settings 1,311/1,311、ui 216/216、updatefs 2,638/2,638，0 解包失败；最终体积分别为 3,729,306、868,927、39,740,072 字节。

## 4.0.0

- PAK 构建由“保留整包后追加修改流和第二份索引”改为紧凑物理顺序重建；未修改压缩流、非索引间隙和别名条目原样保留，彻底消除重复构建导致的体积膨胀。
- 新增发布级结构闸门：条目数、资源标识、偏移边界、数据重叠、唯一末尾索引及所有未修改压缩字节必须完全一致；完整解包全部成功后才发布。
- 构建采用同盘临时文件原子替换，兼容 Windows 跨盘临时目录；验证失败不会覆盖旧 PAK。
- 含 `�`、损坏占位符、控制标记不一致或无法编码的译文自动保留原始资源文本，允许汉化不完整，但禁止把坏译文写进 PAK。
- 修复 PAK 文本回写编码错配：XLSX/翻译记录继续使用 UTF-8，但构建时改为根据原始资源字节检测 UTF-8、GBK/GB18030、TCVN3 或混合编码。UI/装备/技能/任务 INI 不再把中文 UTF-8 写入 GBK 文件，Lua/UTF-8 TSV 仍保持 UTF-8；新增 settings/ui/updatefs 三个 PAK 的实际构建回读验证均通过。
- 补齐 TCVN3 的 Ư/ư + 声调组合（包括 `Ứ`），避免合法越南语姓名触发编码失败而阻止整个 ui.pak 构建。

- 修复“按文件 Ollama”无法读取多 PAK 未翻译 XLSX：自动识别 v7 稀疏映射，不再拿当前单 PAK 映射比较导致全部 ID 不匹配；翻译后统一导入全部 PAK、同步资源并刷新下一轮残留表。
- Ollama 覆盖写回多 PAK XLSX 时保留 `id / pak / source_file / text` 四列，检查点继续按该工作簿独立保存。
- 工具栏新增独立可见的“导出未翻译 XLSX”按钮：一次导出全部 PAK 当前残留的越南文去重片段，译后继续使用原“导入全部 PAK XLSX”按钮。
- 修复完整 XLSX 导入把正常中文数字、斜杠、百分号、箭头及 `BUFF` 等误判为危险译文的问题；安全回退现在区分“去重片段”和“资源引用处数”。
- 多 PAK 导入后自动生成 `remaining_xlsx` 残留专用工作簿，只包含仍有越南文的去重自然语言片段；再次导入稀疏工作簿时保留所有未列出的既有中文，不再从头重翻完整表。
- 残留工作簿从规范源文本生成，避免把中越混合的历史坏译文继续交给 Google；`#d1+` 等选择器和真实控制标签完整留在本地骨架，装饰性 `<Chiến>` 的可见单词仍可翻译。
- Google 在纯文本单元格中凭空加入的 ASCII 数字会安全回退，防止与本地骨架中的原数字重复或错位。
- 修复 INI 玩家界面字段因键名不含 `text/name/title` 而被漏掉：导出全部 PAK 前会增量重扫，当前三 PAK 项目补回 8,987 条记录（含耐久、等级要求、门派、重量等装备面板文字）。
- 完整 XLSX 不再带入含标签、路径、变量、数字、宏或其他运行时结构的历史坏译文；导入端同样拒收这类结构回流。
- 完整 XLSX 导入结果新增剩余越南文记录计数；仍有越南文时明确警告，不再把“文件导入成功”表述为“已经完全汉化”。
- 完整 XLSX 升级为 v7 多 PAK 合并工作簿：一次导出、一次 Google 翻译、一次导入即可更新项目内全部 PAK。
- 完整 XLSX 改用带外精确骨架，运行时标签、变量、格式符、路径、数字及换行控制信息不再进入译文单元格；导入自动原样复原，缺失译文用原文片段补位。
- 裸 `◈`、`ZXQROW`、`{P数字}` 和残留 ph 标记纳入结构污染拦截，旧错误可在资源同步时自动回退原文。
- 主构建按钮改为依次构建全部 PAK；汉化率不再被误作构建门槛，未翻译内容允许保留原文构建。

- 从原版 Studio 建立独立文件队列副本。
- 普通界面收敛为导入、检查、翻译、润色、构建。
- Ollama 改为按资源文件顺序翻译，禁止跨文件混桶。
- 拒绝/修复 `K系统`、`Ph附近` 一类模型残留越南词根。
- 修复导出 XLSX 后同步复制整个 updatefs 导致界面卡死或闪退的问题。
- 默认 XLSX 导出改为每个源文件一份工作簿和专属映射表，支持逐文件 Google 机翻与导回。
- 逐文件导出改为扁平目录；XLSX 导入和 Ollama 均改为选择整个文件夹并自动连续处理。
- XLSX 与配置彻底分目录：`xlsx` 只放工作簿，`config` 集中保存映射、报告、备份和 Ollama 检查点；所有按钮自动关联两个目录。
- 修复旧项目导入后缺少 `_isPlayerVisible` 导致资源同步为 0；逐文件导入会持久化安全来源标记。
- XLSX 导入校验与最终 PAK 控制标记校验统一；Google/Ollama 破坏占位符的译文自动保留原文并单独计数。
- 导入与 Ollama 增加端到端闸门：文件失败、资源同步为 0 或最终回写仍有跳过时不再显示成功。
- 修复“失败文件：0”被弹窗误判为操作失败，以及资源同步读取错误字段始终显示 0 的问题。
- 修复左侧把 TSV 数据行误当表头、将大量名称/说明错误显示成“内部字段”的问题。
- 玩家可见范围改为分析器持久化的唯一白名单，导出、Google/Ollama 导入、人工 CSV 和构建共用该范围。
- XLSX 映射升级为 v6，并明确写入 `player-visible-only`；逐文件导出改为直接枚举白名单，既不会多出内部字段，也不会被二次过滤漏掉展示文本。
- 新导出默认进入 `<pak>_player_visible/xlsx` 与同级 `config`，保留旧 Google 工作簿。
- 修复 Ollama 文件夹续跑仍从 `1/N` 逐个重开工作簿的问题；启动时先核对每个完成报告与 XLSX 修改时间，未改的完成文件直接跳过，部分完成文件继续各自 checkpoint。
- Ollama 进度改为分别显示累计完成、本次直接跳过、本次处理和剩余文件，部分完成不再误计为“完成”。
- Ollama 现在还会按记录 ID 复用 Studio 已导回的合格中文；即使重新选择较旧的越南文 XLSX，也不会把已经由 Google、人工或上轮 Ollama 完成的内容重新送模。

- 修复文件夹进度每进入一个 XLSX 就回到 0% 导致剩余时间虚高；现在按整个文件夹的 XLSX 行数加权，累计进度、速度和 ETA 不再逐文件重置。
