# 游戏本地化「两按钮」流程设计说明（剔除 CSV 版）

> 目标：越南语游戏本地化做成一体化商业工具，全程不出现任何 CSV 中间文件。
> 只有两个按钮：**① 导出 xlsx + 映射表** → 谷歌翻译 → **② 导入 xlsx + 一键润色 + 构建 PAK**。
> 本文件只描述逻辑与数据结构，不涉及代码改动。

---

## 0. 现状为什么有 CSV（先说清，才好剔除）

PAK 里存的是 183 个多列表格文件（`NNNN_哈希.tsv`，如
`TaskIndex/RewardName/RewardIcon/RewardQuantity/RewardDescription`），
文本是 **TCVN3 单字节越南语**。这些文件没有统一的 `id/text` 结构，不能直接丢给谷歌翻译。

所以 `export-text-csv` 做了一层「归一化」：
- 扫描每个 TSV/INI/TXT，找出含越南语的格子（`iter_translatable_cells`）；
- 给每个格子算一个稳定 id（`sha1(pak|文件|行|列|原文)`）；
- 把格子里可译文本抽出来 + 占位符模板；
- 汇成一张大 CSV（86,983 行，`id/text/placeholders`）；
- 同时写 `_text_localization_index.json`，记录**每个 id → 文件/行/列/编码/模板**（回写索引）。

**关键点：回写所需的全部信息都在 index 里**，大 CSV 只是 `id→text` 的薄载体。
因此把大 CSV 换成「xlsx + 映射表」，回写能力一点不少。CSV 可以整个剔除。

---

## 1. 总体数据流

```
┌──────────── 按钮① 导出 ────────────┐
│ extracted/ 183 个 TSV/INI/TXT        │
│   │ 扫描可译格子（TCVN3→unicode）      │
│   │ 按文本去重                         │
│   ▼                                  │
│ master.xlsx（id + text_vn，≤10MB）    │
│ mapping.json（id ↔ 单元格回写索引）     │
└─────────────────────────────────────┘
                │ 交给谷歌翻译（不支持本地执行，需人工/上传）
                ▼
┌──────────── 按钮② 导入 ────────────┐
│ 谷歌翻好的 master_zh.xlsx            │
│   │ 本地一键润色（术语表/模板直译）      │
│   │ 按映射写回每个格子（中文→混合编码）   │
│   ▼                                  │
│ modified/（183 个回写后的 TSV）        │
│   │ build-pak（NRV2B 重建 + 回环校验）  │
│   ▼                                  │
│ updatefs.pak（可回填游戏）             │
└─────────────────────────────────────┘
```

## 2. 数据结构

### 2.1 单元格回写索引（导出时生成，内嵌进 mapping）

沿用现有 index 结构，每条代表**一个可译格子**：

```json
{
  "id": "sha1(updatefs.pak|0007_0130A0F4.tsv|12|3|原文)",
  "source_file": "0007_0130A0F4.tsv",
  "relative_path": "updatefs/0007_0130A0F4.tsv",
  "row": 12,
  "column": 3,
  "mode": "cell | key_value",
  "prefix": "",
  "source": "TCVN3原文",
  "export_text": "抽出的可译文本（unicode）",
  "tokens": [{"key":"P1","value":"\\spr\\item\\..."}],
  "template": "{TEXT} 或含 {P1} 的模板",
  "encoding": "tcvn3 | gbk | ..."
}
```

### 2.2 映射表 mapping.json（导出的产物，导入时唯一依赖）

```json
{
  "version": 3,
  "mode": "xlsx-dedup-cells",
  "pak": "updatefs.pak",
  "extracted_dir": "…/extracted/updatefs",
  "source_rows": 86983,
  "unique_rows": 33599,
  "rows": [
    {
      "id": "1",
      "text": "去重后的越南语（unicode，占位符已掩码）",
      "cells": [
        { "id": "sha1…", "source_file": "…", "relative_path": "…",
          "row": 12, "column": 3, "mode": "cell", "prefix": "",
          "tokens": […], "template": "{TEXT}", "encoding": "tcvn3" },
        { "id": "sha1…", "source_file": "…", "row": 88, "column": 2, … }
      ]
    }
  ]
}
```

**去重规则**：文本（占位符掩码后）完全相同的多个格子 → 共用一个 `id`，挂在同一个 `cells` 数组下。
同一句越南语在游戏里出现多次，谷歌只翻一次，回写时自动填到所有位置。这正是去重的收益。

### 2.3 master.xlsx（导出产物，供谷歌翻译）

两列（Sheet 名「本土化」）：

| id | text |
|----|------|
| 1  | 越南语原文（unicode，占位符掩码） |
| 2  | … |

- 只有 **unique_rows** 行（≈33,599），远小于 10MB，谷歌可直接上传。
- `id` 为纯数字（mapping 里的 `id`）。

### 2.4 master_zh.xlsx（谷歌翻译返回）

同结构：`id` + `text`（中文）。只允许出现 mapping 里存在的 id，多余/缺失都要拦截。

## 3. 按钮① 导出：xlsx + 映射表

输入：`extracted/` 目录（183 个 TSV/INI/TXT）
输出：`master.xlsx` + `mapping.json` + `mapping.csv`（可选，便于人工查看）

步骤：
1. **扫描**：对每个 `.tsv/.ini/.txt` 逐行逐格跑 `iter_translatable_cells`，
   得到 `id + 单元格回写信息 + export_text`。跳过：无候选字节、非越语/混合语言、
   资源引用（`.spr`/路径）、不可译短串。
2. **编码归一**：`decode_best` 把 TCVN3 单字节还原成 unicode 越南语，供翻译。
3. **掩码**：`token_template` 把 `\spr\...`、`{xxx}`、`%s` 等受保护 token 抽成 `{P1}{P2}…`
   占位符，避免谷歌翻译破坏。
4. **去重**：按掩码后文本分组，同文共用一个 `id`，收集其所有 `cells`。
5. **写 xlsx**：`openpyxl` 写入 `id + text`（≈33,599 行）。
6. **写 mapping**：`id ↔ cells` 完整回写索引。
7. **报告**：源行数 / 去重行数 / 涉及文件数 / 文件大小（校验 ≤10MB）。

---

## 4. 按钮② 导入：润色 → 回写 → 构建 PAK

输入：`master_zh.xlsx` + `mapping.json` + `extracted/` + 原始 `updatefs.pak`
输出：`updatefs.pak`（构建产物）+ 报告

步骤：
1. **读翻译**：解析 `master_zh.xlsx`，`id → 中文`。
   校验：id 必须都在 mapping 里；缺失的 id 记录为 `skipped`（保留越南语原文）。
2. **本地一键润色**（复用 `polish_localizer.py` 逻辑，纯本地）：
   - `SOURCE_OVERRIDE`：源越南语精确命中 → 直接采用标准译名（十大高手/十大杀手…），不走谷歌输出；
   - `EQ`：装备模板直译（`Tinh Quân*Huyền Thiết Phi Phong*Ma Cấp 1 (+1)` → `星君*玄铁披风*魔阶1(+1)`）；
   - `CANON`：术语规范化（大师→高手、刺客→杀手）；
   - `TERM`：残留越南语清理；
   - `FALLBACK`：缺失条目补译。
3. **还原占位符**：`restore_template(润色后中文, cell.template)` 把 `{P1}` 还原成原 token。
4. **校验**：`validate_translation(源, 目标)` 确保受保护 token（路径/格式符/URL）没丢。
5. **编码回写**：`encode_cell(中文, 原格子字节, encoding)` 用 `encode_text_for_source`
   把中文转回游戏混合编码（中文→GBK/GB18030，越南语字符→TCVN3 单字节）。
   对 `key_value` 模式格子，保留 `key=` 前缀。
6. **写 modified/**：复制 extracted → 逐格回写 → 只保留改动的文件。
7. **构建 PAK**：`build_from_modified_dir(原始pak, extracted, modified, 输出)`，
   NRV2B 压缩重建，并做 **回环校验**（重建后再解包逐字节比对，失败即拒绝输出）。
8. **同步 records（可选但推荐）**：把译文回写进 `text_records.json` / `localization.db`，
   让应用的「已翻译/未翻译」状态一致，避免下次重复导出同一批。

## 5. 安全性 / 校验清单（不降级）

| 项 | 检查 | 失败处理 |
|----|------|----------|
| 映射完整性 | xlsx 每个 id 都在 mapping 里，无未知 id | 报错列出 |
| 缺失译文 | 有 id 无译文 | 保留越南语原文，计入 skipped |
| 占位符 | `restore_template` 后受保护 token 齐全 | 该格子跳过，计入 risk |
| 编码 | 中文字符必须能编进游戏混合编码 | 报错给出字符，拒绝构建 |
| 文件/行/列 | 回写时原文件行数、列数、原 id 不变 | 报错，拒绝该文件 |
| 回环 | 重建 PAK 解包后逐字节比对 | 不一致即拒绝输出 |
| 大小 | 导出 xlsx ≤ 10MB | 报错提示 |

## 6. 复用的现有模块（不新造轮子）

| 能力 | 来源 |
|------|------|
| 扫描可译格子 + 稳定 id | `tsv_localization.iter_translatable_cells` |
| 占位符掩码/还原 | `tsv_localization.token_template` / `restore_template` |
| 受保护 token 校验 | `tsv_localization.validate_translation` |
| TCVN3 解码 / 编码回写 | `localization_analyzer.decode_best` / `encode_text_for_source` |
| 一键润色（术语/模板） | `polish_localizer.py`（本项目已写好） |
| 去重 + 映射 | `merged_csv` 的去重逻辑（去掉分片，改出 xlsx） |
| PAK 重建 + 回环校验 | `pak_builder.build_from_modified_dir` |

## 7. 相比旧流程的差异

| 环节 | 旧流程 | 新流程 |
|------|--------|--------|
| 中间格式 | 34 个 CSV 分片 + 完整 CSV | 单个 xlsx + 映射表 |
| 用户操作 | 手动管 34 个文件 | 一个文件，谷歌翻完丢回来 |
| 一键润色 | 无（或独立脚本） | 内嵌进导入按钮 |
| 构建 | 独立 build 步骤 | 导入按钮内自动完成 |
| 回写索引 | 依赖 index + 完整 CSV | 内嵌在 mapping 里 |
